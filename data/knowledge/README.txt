БАЗА ЗНАНИЙ TRAVEL PLANNER
Версия 0.4.0. Дата исследования 21 ноября 2026 года.

Объём

В places.json находятся 742 карточки по 16 городам России. Из них 103 карточки имеют статус map_imported. Добавлены 14 гастрономических мест с чтением сайтов заведений или туристических порталов.

Для всех городов получены отдельные картографические выборки. map_candidates.json содержит 5855 объектов OSM с названиями, координатами при наличии геометрии и исходными тегами. В карте могут быть заполнены адрес, часы работы, кухня, сайт, условия доступа, сезонность и другие сведения. Исходные теги сохранены.

В каждом городе представлены гастрономические места. Распределение остальных категорий можно проверить в category-coverage.csv. Панорамы, семейные развлечения, спорт и сувениры представлены по городам неравномерно.

Источник и охват карт

Для автоматического сбора выбран OpenStreetMap. Основной способ выгрузки — Overpass API. Из-за ошибок 502 и таймаутов некоторые города выгружены небольшими центральными кварталами через API OSM. Объём охвата каждого города, границы прямоугольника, запрос, дата и история ошибок находятся в map_sources.json и map-coverage.csv.

Картографические выборки охватывают центральные районы и отдельные кварталы. Полный охват городской территории требует следующего расширения. Проверка принадлежности объектов административной границе города отражена значением boundary_verified=false.

OSM предоставляет открытые данные по ODbL. Атрибуция и ссылки на лицензию находятся в OSM-ATTRIBUTION.txt. Источник каждого картографического объекта доступен по source_url. Сведения о собственном хранении данных коммерческих карт проверяются по условиям выбранного поставщика. Документация бесплатного API Яндекса описывает ограничение на сохранение результатов геокодирования и других данных в собственной БД.

Статусы карточек и сведений

record_status=researched_draft обозначает исследованную карточку с сохранёнными источниками. record_status=map_imported обозначает карточку, сформированную из тегов OSM. Для проверки работы заведения и условий посещения в ней сохранены unresolved_fields.

checked_on фиксирует дату чтения. Дата обследования объекта берётся из исходных тегов, когда она присутствует. Наличие объекта в актуальной выгрузке карты требует дополнения сведениями о фактической работе заведения.

Источники карт дополнительно сопоставлены с 42 карточками. При сопоставлении сохраняются идентификатор OSM и способ сопоставления в map_matches.json. Существовавшие координаты карточки сохраняются. У карточки с отсутствующими координатами может появиться точка из OSM. Погрешность точки и расположение входа требуют проверки.

kind=osm_node означает точку объекта OSM. kind=osm_way_center и osm_relation_center означают центр геометрии, полученный от Overpass. kind=osm_way_representative_point означает точку внутри контура, вычисленную при обработке небольшой XML-выгрузки. kind=source_map_marker означает точку из первоначального источника. entrance_verified показывает отдельную проверку входа.

opening_hours.status=official_source_read означает чтение часов на сайте учреждения. portal_reported означает сведения туристического портала. map_reported означает запись из OSM. unknown обозначает отсутствие пригодных сведений.

У 19 карточек часы прочитаны на первичных сайтах, у 6 — на туристических порталах, у 79 карточек сохранена запись OSM. Среди первичных сайтов есть неполные и противоречивые расписания, отражённые в notes и unresolved_fields.

opening_hours.raw сохраняет исходную строку OSM. Для неё требуется календарный разбор, включая праздничные дни и сезонные исключения. weekly содержит недельные интервалы только при наличии достаточных сведений. closes_next_day=true обозначает закрытие после полуночи следующего дня. Пустой weekly=null сохраняется при неполном или противоречивом графике.

У Новосибирского зоопарка расходятся часы в шапке и разделе для посетителей. На сайте волгоградского «Бамберга» расходятся основной график и нижнее меню. У московского Центрального рынка и «ОнегинДачи» опубликован неполный недельный график. В карточках сохранены прочитанные сведения и вопросы для уточнения.

Цены на билеты находятся в admission. Сведения о среднем чеке ресторана отражены в research_notes с источником и условиями. visit_duration с basis=editorial_estimate является оценкой длительности остановки. Для ресторанов она включает приём пищи. Переходы и очереди учитываются отдельно.

description_basis=source_excerpt обозначает короткую выдержку из источника. editorial_summary обозначает составленное описание. Описания картографических карточек основаны на названии и тегах объекта.

Проверка качества

quality_issues.json хранит найденные конфликты координат, расписаний, сайтов и сопоставлений. unresolved_fields хранит пробелы каждой карточки. В sources.json указан способ чтения источника. Ссылка на сайт из карты имеет official_url_status=linked_from_map. Статус official_source_read обозначает отдельное чтение сайта.

Приоритет подбора новых карточек определялся разнообразием категорий и заполненностью сведений. Популярность и пользовательские рейтинги требуют отдельного источника. Некоторые одинаковые названия относятся к разным филиалам, поэтому при сопоставлении учитываются координаты и адрес.

Для двух петербургских фортов и Омского музея просвещения сохраняются конфликты исходных координат. Точный вход и возможность посещения для маломобильных гостей требуют дополнительной проверки в большинстве карточек.

Маршруты

route_templates.json содержит 48 черновиков, по 3 на город. Три петербургских шаблона составлены редакционно. Остальные 45 автоматически скомпонованы по теме и близости опубликованных точек. Для конкретной даты проверяются часы работы, условия входа и переходы. Показатели distance_meters и walking_minutes заполняются после подключения маршрутизатора.

Текущие карточки и маршруты имеют route_ready=false. Данные пригодны для импорта, поиска по категориям и разработки планировщика с учётом статусов источников и пробелов.

Повторная проверка

Требуются Python 3 и jsonschema версии 4 или выше. Команда из каталога data/knowledge — python3 validate_knowledge.py.

Проверяются уникальность ID, схема карточек, ссылки на города и категории, родительские связи, маршруты, соответствие CSV, счётчики и сопоставления карт. По каждому городу проверяются минимум 30 карточек и 3 шаблона. Расширение количества карточек следует разнообразию доступных мест.

Следующее пополнение

Приоритетными остаются условия посещения и входы у мест, используемых в маршрутах. Далее уточняются расписания с праздничными исключениями, цены, запись и возрастные ограничения. Картографический охват расширяется за пределы центральных участков. Новые объекты проходят сопоставление по идентификатору, названию, адресу и географии.

Основной бэкенд начинается с текущего представления данных. Второй разработчик подключается к реализованным API. Выбор модели остаётся за ним.
